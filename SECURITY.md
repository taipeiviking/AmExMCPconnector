# Security policy

This repository handles a design for sensitive local financial data. Do not open a public issue containing a vulnerability exploit, credential, OAuth token, account identifier, statement, transaction, log, database, export package, or diagnostic bundle.

Use a private GitHub Security Advisory for vulnerability reports. Include the smallest synthetic reproduction possible and remove machine/user paths. If private reporting is unavailable, open a metadata-only issue asking the maintainer to establish a private channel; do not include the security details there.

The current `0.x` repository is a runnable local alpha, not audited financial software. Use the synthetic test drive first. Its encrypted local persistence, Japan import, reviewed export packages, read-only MCP boundary, Windows secret resolution, and built-in Plaid Hosted Link/Transactions path have automated tests, but they have not received an independent production security audit. Test the U.S. path first with your own Plaid Sandbox app and fake data. Live Plaid Production use requires the owner's separate Plaid approval, verified American Express Transactions coverage, exact read-only product review, installer signing/update controls, operational recovery, and independent security/privacy review. The implementation is not evidence of a verified live Amex connection. Treat real statement testing as sensitive local evaluation and verify every preview row against the official source.

The Plaid flow keeps its developer app registration in Windows-protected references, isolates each account's access token and Item/grant, opens consent only at a validated Plaid HTTPS destination in the system browser, and distinguishes provider Item removal, institution-side revocation, local token removal, credential removal, and local financial-data deletion. A normal credential check does not prove Production institution/product availability. Do not place an Amex password, Plaid secret, Link/public/access token, real account data, or consent screen in `.env`, source control, screenshots, logs, or support reports.

Supported security fixes target the current `main` branch until the first signed release policy is published.
